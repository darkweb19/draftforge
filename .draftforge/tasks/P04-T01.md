# P04-T01 — Execution contracts, durable attempts, and dependency scheduler

Status: done

## Objective

Build the provider-independent Phase 4 foundation: parse approved task
contracts, select dependency-ready and path-compatible work, claim stable
execution attempts under the project lock, persist schema-validated attempt
manifests and redacted evidence, and reconcile readiness without holding a lock
across worker side effects.

## Acceptance criteria

- A strict task-contract parser reads the task named by `TaskState.taskFile`,
  validates its ID, dependencies, owned paths, required context, ADRs,
  acceptance criteria, verification, exclusions, and optional budget, and
  rejects missing sections, path escapes, glob ownership, or state/contract
  disagreement before a claim.
- Planning contracts support optional per-task time, token, and cost budgets;
  generated task files preserve them. The effective wall-clock budget is the
  task override or `limits.taskTimeoutMinutes`; token/cost declarations are
  recorded for Phase 5 accounting rather than falsely reported as enforced.
- The pure scheduler selects only tasks in the active phase whose dependencies
  are `done`; it counts existing active attempts, honors
  `roles.worker.maxConcurrency`, and detects exact plus ancestor/descendant path
  conflicts using repository path semantics, including Windows case behavior.
- Readiness recomputation and attempt claims happen under the project lock.
  Concurrent claimers cannot reserve the same task, and the lock is released
  before worktree creation or model execution.
- Canonical task state carries a nullable `{ runId, attemptId }` reference.
  The versioned state migration preserves existing progress, and
  `workflow.currentTask` is documented and rendered as a display pointer rather
  than the source of truth for concurrent work.
- Every claim has a schema-valid atomic manifest under
  `.draftforge/runs/<run-id>/` before canonical state references it. Manifests
  include contract hash, base commit placeholder, deterministic workspace
  identity, lifecycle state, timestamps, and evidence pointers.
- Attempt events and evidence are idempotent and redacted, including configured
  environment secret values. A result artifact can be persisted before a state
  transition and recovered without a duplicate worker call.
- A worker-owned path can never include canonical state, `SESSION.md`, or run
  control artifacts; those remain scheduler-owned.
- New schema templates are byte-identical to repository copies, initialized
  projects receive the execution schema/run layout, and `npm run check` passes.

## Exclusions

- No Git worktree implementation.
- No worker prompt, model call, or result-envelope parsing.
- No `run` or `resume` CLI command.
- No reviewer invocation, repair loop, merge, rollback, secret scan, or usage
  accounting.
