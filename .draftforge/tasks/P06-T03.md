## Acceptance criteria

- README status matches canonical Phase 6 state and leads with user installation and the shortest working local flow, clearly separating repository-development commands from installed-package commands.
- Installation documents Node.js 22, supported operating systems, the scoped-package placeholder until P06-T04 locks an owned registry identity, local tarball installation for release candidates, and clean uninstall.
- Provider setup gives copyable configuration for `codex-cli`, `claude-cli`, `openai-api`, and `anthropic-api`, distinguishes workspace-capable workers from text-only routes, names environment variables without showing values, and uses Claude/Anthropic in automation examples.
- A committed example starts from a concrete `idea.md`, shows planning approval and delegated run/review/resume with expected transitions, and has a deterministic no-provider path package smoke can validate.
- Upgrade guidance explains backups, supported migrations, no-op behavior, in-flight refusal, modified managed files, future-version refusal, and manual recovery without promising automatic rollback.
- Troubleshooting covers harness/API authentication, dirty-root integration refusal, retained worktrees, lock recovery, blocked tasks, Windows shims, package installation, and safe evidence collection that excludes secrets.
- SECURITY.md defines supported release reporting, secret handling, worktree/run-artifact risks, verification limits, provider trust boundaries, and a private vulnerability-reporting path without inventing an external account.
- Documentation commands and internal links are checked locally, and `npm run check` passes.

## Verification

- Run `npm run check`.
- Run the documented local-tarball quickstart and deterministic example with the built installed binary.
