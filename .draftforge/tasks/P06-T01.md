# P06-T01 — Portable npm artifact and installed executable smoke

Status: ready

## Objective

Create the deterministic package foundation for Phase 6: make a clean checkout
build and pack itself, make the actual npm-installed `draftforge` executable run
on every supported platform, derive the CLI version from package metadata, and
prove the artifact can scaffold and inspect a project without network access.

## Acceptance criteria

- A clean checkout can run `npm pack` through a declared package script without relying on an ignored pre-existing `dist/`; the build runs first and a failed build cannot produce a release candidate.
- The packed artifact contains only runtime files, templates, README, license, and package metadata, with no source tests, local configuration, run artifacts, environment files, Git metadata, or generated evidence.
- Installing the tarball into a clean temporary directory and invoking the package manager's generated binary succeeds through the POSIX symlink path and the real Windows npm shim; direct `node dist/cli.js` execution is not accepted as package smoke.
- Installed `draftforge --version` exactly matches `package.json`, with no second handwritten version constant that can drift.
- The installed binary runs `init`, `status`, and `handoff` against a clean temporary project, and the generated project passes state, configuration, handoff, and template checks without a provider, credential, or network call.
- Package smoke is an npm script later CI jobs can call against one explicit tarball path; temporary artifacts are outside the repository or cleaned conservatively and never staged.
- The package remains private in this task; P06-T04 selects a verified public npm scope, and the occupied unscoped `draftforge` registry name is never assumed available.
- Existing CLI behavior remains covered and `npm run check` passes.

## Verification

- Run `npm run check`.
- Run the package-smoke npm script from a clean build and invoke the installed `draftforge --version`, `draftforge init`, `draftforge status`, and `draftforge handoff` commands.

## Exclusions

- No persistent project-state upgrade or schema refresh; P06-T02 owns them.
- No user documentation, GitHub Actions, registry publication, or release tag.
- No provider or harness model call during package smoke.
