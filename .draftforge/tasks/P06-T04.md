# P06-T04 — Cross-platform CI, scoped publication, and npm provenance

Status: backlog

## Objective

Create the least-privilege automation that checks DraftForge and its exact npm
artifact on supported operating systems, then publishes a tag-matched,
provenance-bearing scoped package through npm trusted publishing only after its
registry identity is explicitly verified.

## Acceptance criteria

- Pull requests and pushes run `npm ci`, `npm run check`, clean packing, tarball inspection, and installed-binary smoke on real Ubuntu, macOS, and Windows; the matrix includes Node.js 22 and any additional lane cannot replace the minimum-runtime lane.
- CI caches only npm download data, never `node_modules`, build output, tarballs, DraftForge run artifacts, local configuration, or environment files; jobs use minimal permissions and pinned current action versions.
- The release workflow triggers only from an intentional version tag, verifies the tag matches `package.json`, rebuilds from the tagged clean commit, runs the same checks, and publishes the exact tarball that passed smoke rather than rebuilding in the publish step.
- Before publication, the user supplies an npm scope they demonstrably own and configures its trusted publisher; metadata uses that scoped name, public access, MIT license, repository, issues, runtime engine, and a non-placeholder version, while release checks reject unscoped `draftforge`.
- npm publication uses trusted publishing/OIDC with provenance and no stored long-lived token; the publish job has only permissions required for checkout, artifact retrieval, identity, and provenance.
- Fork pull requests and ordinary pushes cannot publish; a tag/version mismatch, private identity, unexpected tarball, failed matrix job, or missing trusted-publisher setup fails before `npm publish`.
- Workflow tests parse YAML and package metadata to guard triggers, permissions, matrix coverage, artifact identity, provenance, and secret absence; routine local tests do not call GitHub or npm.
- `npm run check` passes.

## Verification

- Run `npm run check` and `node scripts/release-check.mjs` against a locally packed tarball.
- On GitHub, require green Ubuntu, macOS, and Windows installed-artifact jobs before testing the tag-gated publish path.

## Exclusions

- No publication under the unscoped `draftforge` name.
- No classic npm automation token, password, OTP, or secret value in files, logs, fixtures, workflow inputs, or task evidence.
- No public publish until the user confirms the owned scope and trusted publisher configuration.
