# P05-T04 — Reported usage capture, run ledger, and budget enforcement

Status: backlog

## Objective

Account for what API runs actually cost. Surface provider-reported token usage
through the adapter port, aggregate it into a durable per-run ledger, and enforce
declared token and cost budgets before a call is issued — recording an honest
`unknown` wherever a provider reports nothing.

## Acceptance criteria

- The adapter result type carries an optional reported-usage record with input,
  output, and total tokens. The API adapters populate it from the provider
  response; the harness adapters leave it absent, and the shared contract test
  suite asserts both behaviors.
- Absent usage is represented as `unknown` everywhere it surfaces. No code path
  estimates tokens from text length, and a test asserts an unknown total never
  becomes a number.
- Cost is derived only where a price is known for the resolved model, from a
  single table in the provider layer; an unpriced model yields an unknown cost
  rather than zero.
- A run-level ledger under `.draftforge/runs/<run-id>/usage.json` records per
  call the role, adapter, resolved model, task id, attempt id, reported tokens,
  and derived cost. Writes are atomic and append-safe across concurrent
  dispatch, and repeated reconciliation never double-counts a call.
- Declared `tokenLimit` and `costLimitUsd` budgets are checked before a call is
  issued using the attempt's accumulated usage. An exceeded budget refuses the
  call and yields `harness-failure` with an actionable message; work is never
  truncated mid-flight to fit a budget.
- No ledger entry, event, or error message contains a prompt, a completion, an
  environment value, or an API key.
- `npm run check` passes, including the existing provider contract suites for
  every adapter.
