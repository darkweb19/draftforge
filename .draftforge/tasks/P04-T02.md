# P04-T02 — Git-worktree workspace isolation and inspection

Status: done

## Objective

Implement the isolated workspace boundary independently of scheduling: create,
locate, inspect, and conservatively preserve deterministic Git worktrees for a
task attempt, and derive authoritative changed paths from Git without shell
execution or network access.

## Acceptance criteria

- A provider-independent workspace port exposes create-or-recover, inspect,
  changed-path, process-liveness, and conservative cleanup operations using a
  stable attempt identity.
- The Git adapter uses an injectable shell-free child-process boundary and no
  provider SDK or provider-layer import.
- Each attempt maps deterministically to
  `.draftforge/runs/<run-id>/worktrees/<task-id>` and an isolated branch. The
  adapter records/returns the base commit and refuses to reuse a path or branch
  whose Git metadata belongs to another attempt.
- Repeating create-or-recover for the same attempt is idempotent; interrupted
  setup can be discovered; dirty or uncertain worktrees are preserved rather
  than deleted.
- Changed paths come from the actual Git worktree, including staged, unstaged,
  deleted, renamed, and untracked files. Output is normalized to safe
  repository-relative paths and never trusts a worker-reported path list.
- Abort/timeout handling reports whether the child is definitely terminated.
  An uncertain live process prevents workspace reuse so two workers cannot edit
  one worktree concurrently.
- Tests use temporary local repositories, injected process fakes where useful,
  and no network. They cover POSIX and Windows path/command behavior,
  idempotency, metadata mismatch, dirty preservation, and complete diff
  discovery.
- `npm run check` passes.

## Verification

- Run `npm run check`.

## Exclusions

- No scheduler, task-state transition, or run manifest persistence.
- No model invocation or worker result parsing.
- No automatic merge into the primary branch.
- No destructive cleanup of uncertain or modified worktrees.
