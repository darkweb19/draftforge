# P06-T02 — Explicit project upgrade, backup, and compatibility fixtures

Status: backlog

## Objective

Turn the existing in-memory state migrations into a deliberate, recoverable
project upgrade workflow that preserves user files, refuses unsafe conditions,
refreshes recognized DraftForge-owned schemas, and proves supported older
projects remain usable after the installed package advances.

## Acceptance criteria

- `draftforge upgrade` is the only command that persists a schema upgrade; ordinary `readProjectState`, `status`, and `handoff` may validate a supported in-memory migration but never silently rewrite canonical files.
- Upgrade runs under the project lock, parses the raw on-disk version, computes and strictly validates the complete target state before mutation, and reports a no-op when already current.
- Before the first write it creates a recoverable timestamped backup of every file it will replace; a failed write leaves an actionable recovery path, never reports success, and backs up no environment value, local credential, or run artifact.
- Supported version 1 and 2 fixtures upgrade to version 3 without losing task status, attempts, decisions, or handoff content; future versions and downgrade requests fail before any file change.
- Upgrade refreshes only DraftForge-owned schema files whose bytes or recorded fingerprints match a known shipped version; a user-modified or unrecognized managed file blocks with its path named and is never overwritten.
- Projects with active worker/reviewer work, a live process, or uncertain recovery artifacts are refused before mutation; idle projects upgrade, render a matching `SESSION.md`, pass `status`, and can enter ordinary reconciliation without duplicate model calls.
- CLI help, exit codes, and tests distinguish current, upgraded, refused, and failed-with-backup outcomes; no test reads a real credential or makes a provider/network call.
- Repository and template schemas remain byte-identical and `npm run check` passes.

## Verification

- Run `npm run check`.
- Build the CLI, upgrade deterministic version 1, version 2, current, future, modified-schema, and in-flight fixtures, then run installed `draftforge status` on every accepted result.

## Exclusions

- No automatic downgrade or rollback command.
- No overwrite of AGENTS.md, CLAUDE.md, PHASES.md, task contracts, ADRs, idea files, local configuration, or run evidence.
- No npm publication or GitHub workflow.
